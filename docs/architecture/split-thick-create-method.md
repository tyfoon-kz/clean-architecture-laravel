# Split thick create method

До CQRS соблазнительно держать один большой метод create(): он принимает форму, валидирует, сохраняет, строит ответ, отправляет событие и готовит таблицу.

В учебной структуре command меняет состояние, query читает представление, а Presentation adapter решает, как вернуть ответ конкретному actor. Это создает больше файлов, но снижает связность между UI, storage и business process.
